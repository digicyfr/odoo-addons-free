# Security and privacy

- Website designers can create, scan, and delete runs. Restricted website editors can read run and issue metadata. The addon does not grant either role new access to `website.page` or `ir.ui.view`; only designers receive the native editor action.
- Odoo's website editor/designer roles apply to all websites, not one website per user. Users with those roles can read audit metadata for other websites in the same allowed company. Each scan itself selects pages from one chosen website only. Separate website-level staff entitlements are outside this release.
- Global record rules restrict runs and issues to active companies. Issue reads also require a currently active, published, public page. A live override check hides a global-page issue if an active website-specific page with a URL and the same key or URL appears after the scan, even if that replacement is unpublished. The scan searches pages under the caller's normal Odoo rights and selected website; it does not use `sudo()` or a public controller.
- Public methods check role and record access. A run can be scanned once; direct RPC cannot set its result fields or create or edit issue rows. A row-level database lock prevents two concurrent scans of one run. Runs have no scheduler. Deleting a run cascades to issues; deleting a page cascades to its issue rows.
- Stored issue fields contain metadata and SHA-256 hashes only. There are no attachments, page bodies, rendered HTML copies, external requests, credentials, or telemetry. Ignored terms are user-supplied configuration and may contain brand names; do not enter secrets. Retention is manual by deleting old runs.
- The report is advisory. It does not assert that identical static text is untranslated, that an empty SEO title is a defect, or that an image has passed WCAG checks. A scan that reaches a bound or encounters malformed XML is visibly marked truncated or failed.
