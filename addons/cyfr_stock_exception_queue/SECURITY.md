# Security and privacy

- Inventory Users can read scopes and snapshot rows. Only Inventory Administrators may create/edit/delete scopes or invoke manual refresh. Rows have no user write/create/delete ACL. Cron writes through explicit sudo after verifying company and location scope.
- Global record rules restrict both models to active companies. Scope validation requires a company-owned internal location within the selected warehouse's stock subtree and limits each scope to 50 eligible internal locations. Quant and orderpoint reads use that company and location. Products may be shared, owned by the company, or owned by a parent company according to Odoo's pinned product company domain. Consigned quants are excluded.
- Snapshot searches, direct reads, exports and drilldowns also enforce the caller's current linked product, location and warehouse record rules. A later rule change can hide a previously scanned row. Raw SQL is confined to candidate product ID discovery during an authorized scan; rows are built from stock ORM reads under the scope company.
- The scan stores only stock product/location identifiers, numeric quantities, severities, timestamps and a short cron error. It makes no network requests and stores no credentials. Do not put customer data in scope names.
- A scanner with Administrator access can see the stock data of their active companies. Assign Inventory Administrator only to trusted staff. The snapshot is advisory and may become stale between scans; it must not be used as an authorization to ship or procure goods.
- The cron runs as Odoo's system user every five minutes. It processes one bounded batch for one active scope per invocation, rotates by last batch time, and persists a shortened error if that scope fails. A user with only Inventory User access cannot trigger refresh through RPC.
