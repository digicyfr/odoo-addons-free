# Security and privacy

Only users in `point_of_sale.group_pos_manager` have model access. Global record rules restrict each transient scan and row to its owner and allowed companies. The scan checks the user's group, scan ownership, selected POS company, and POS read access before executing. Catalog products and tax configurations are read with the caller's rights; only generated transient-row storage and internal scan-result fields use superuser mode. Row create/write/delete is blocked for normal users, including managers, so RPC callers cannot forge matrix rows. The export reads only rows allowed to the caller and uses the same owner/company check. Source/result tax navigation checks row read access and scan scope, then opens tax records under the caller's normal access rights. No controller, telemetry, external network request, credential or persistent tax copy is added.

CSV cell text beginning with spreadsheet formula characters is escaped. Export contains product, company, scenario and tax labels/IDs from the current page; distribute it as sensitive business configuration. Odoo's normal transient cleanup removes old scans. To report a vulnerability, contact `security@digicyfr.com`; do not post a secret or exploit in a public issue.
